# Release Notes: Workflows Feature

## New Feature: Workflows

### Description
The new **Workflows** feature in Facets empowers Terraform module developers by allowing them to define reusable, operational workflows within their modules. These workflows, termed as *utility modules*, extend the functionality of Terraform modules beyond infrastructure provisioning to include operational tasks such as pod restarts, database migrations, and cluster scaling. Once defined, these utility modules are converted into executable Tekton Tasks within the Facets control-plane Kubernetes cluster, enabling users to trigger and monitor them through the Facets UI or API.

### Use Cases
- **Operational Management**: Automate routine operational tasks like restarting pods or scaling resources.
- **Database Administration**: Execute database migrations as part of a continuous delivery pipeline.
- **Custom Workflows**: Define and execute bespoke workflows tailored to specific operational needs.

### Usage Instructions

#### 1. Defining a Utility Module
Developers can define utility modules within their Terraform modules using a YAML format. Each utility module must include:
- `name`: The identifier for the workflow.
- `steps`: An ordered list of steps, specifying the container images and commands to execute.
- `params`: A list of input parameters that the workflow accepts.
- `acc_type`: The targeted cloud or system type, such as `aws`, `k8s`, `gcp`, or `azure`.

**Example YAML Definition:**
```yaml
name: migrate_database
acc_type: aws
params:
  - name: target_db_url
    type: string
  - name: dry_run
    type: bool
steps:
  - image: myorg/db-migrator:latest
    command: ["./migrate"]
    args: ["--url", "$(params.target_db_url)", "--dry-run=$(params.dry_run)"]
```

#### 2. Publishing a Module
Upon preview or publishing of a Terraform module, the Facets backend:
- Parses the utility modules.
- Registers each as a Tekton Task within the control-plane cluster.
- Labels each Task for resource association and makes them discoverable in the module registry.

#### 3. Discovering and Triggering Workflows
Within the Facets Resource Center UI, users can:
- View the **Workflows** section for each resource, displaying available Tasks with names and step summaries.
- Initiate a workflow using the **Trigger button**, which prompts for any required parameter values.

#### 4. Monitoring and Execution History
- Users can monitor workflow execution status and view detailed logs of each step.
- The UI provides a history table of past TaskRuns, including timestamps and statuses.
- Logs for each step are accessible, and completed TaskRuns are stored for historical review.

### Future Considerations
- Implement Role-Based Access Control (RBAC) for granular permissions.
- Support bulk workflow executions across multiple resources.
- Introduce notifications or webhooks for workflow completion or failure.
- Allow custom outputs from workflows to be captured and returned to users.
