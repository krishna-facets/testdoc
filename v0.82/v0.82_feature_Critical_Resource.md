# Release Notes: Critical Resource Feature

## Overview

The Critical Resource feature in Facets empowers users to mark certain infrastructure components as critical, thereby safeguarding them against accidental or unauthorized changes. This feature is crucial for protecting high-stakes resources—like production databases, Kubernetes node pools, or persistent storage—from unintended disruptions that could lead to downtime or data loss.

## What Is a Critical Resource?

A resource is designated as critical if:

- The module YAML includes `critical: true`.
- Specific fields within the module are marked as critical using the `x-ui-critical` identifier.

Only users with the `write_critical_resources` permission have the ability to:

- Delete the critical resource.
- Change the resource's status (enable/disable).
- Edit fields marked as `x-ui-critical`.

Users lacking this permission will find these actions disabled or set to read-only.

## Why Mark Resources as Critical?

In complex environments, even minor mistakes—like altering a field or disabling a live service—can cause significant downtime or data loss. While tools like `prevent_destroy` in Terraform offer some level of protection, they fall short when a resource is entirely deleted or disabled from the blueprint.

By marking a resource as critical, Facets delivers a comprehensive control mechanism that:

- Prevents accidental deletion or disablement.
- Restricts changes to sensitive fields.
- Establishes clear boundaries through role-based access control (RBAC).
- Ensures traceability via audit logs.

## How It Works

### For Critical Resources

- Cannot be deleted or disabled by users without the required permission.
- Fields marked with `x-ui-critical` are read-only unless the user has permission.
- All actions are logged with full context (who, what, when).

### For Non-Critical Resources

- Function as usual with no restrictions on status changes or field edits.
- Accessible and editable by any user with general permissions.

## Use Cases

- Prevent accidental deletion of **production databases**.
- **Protect Kubernetes node pools** from scale-down or misconfiguration.
- Ensure only authorized personnel can change **resource limits, persistent disk size, or compute allocations**.

## How to Use Critical Resources

To mark a resource as critical, include `critical: true` in its module YAML. For fields that should be protected, use the `x-ui-critical` identifier within the module schema.

## Permissions and Auditability

**Permission Required**: Only users with the `write_critical_resources` permission can make restricted changes to critical resources.

**Audit Logs**: Every critical action (delete, disable, modify critical fields) is logged with a timestamp, user ID, and resource ID, ensuring traceability and compliance across your infrastructure operations.

## Summary

The Critical Resources feature in Facets offers a robust safeguard for infrastructure components that require careful handling. By embedding this control directly into the platform, teams gain confidence that production-grade systems are protected from accidental or unauthorized modifications. The result: safer operations, cleaner access controls, and greater peace of mind across your engineering organization.
