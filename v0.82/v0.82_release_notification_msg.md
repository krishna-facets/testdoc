### Critical Resource
## Critical Resource Feature Overview

The Critical Resource feature in Facets is designed to safeguard sensitive infrastructure components by restricting certain actions such as deletion, disabling, and editing of sensitive fields. This feature is particularly crucial for high-stakes components like production databases, Kubernetes node pools, and persistent storage, where unintended changes can result in downtime or data loss.

### What Is a Critical Resource?

A resource is marked as critical if:

- The module YAML includes `critical: true`.
- Certain fields are tagged as critical using **x-ui-critical**.

Only users with the *write\_critical\_resources* permission can:

- Delete the resource.
- Change its status (enable/disable).
- Edit fields marked as **x-ui-critical**.

Users without these permissions will find these actions disabled or read-only.

### Why Mark Resources as Critical?

Marking resources as critical provides:

- Protection against accidental deletion or disablement.
- Restrictions on changes to sensitive fields.
- Role-based access control (RBAC) to enforce explicit permissions.
- Audit logs for traceability and compliance.

### How It Works

#### For Critical Resources

- Cannot be deleted or disabled by unauthorized users.
- Sensitive fields are read-only unless the user has permissions.
- All actions are tracked in audit logs.

#### For Non-Critical Resources

- No restrictions on status changes or field edits.
- Accessible and editable by users with general permissions.

### Use Cases

- Prevent accidental deletion of **production databases**.
- Protect **Kubernetes node pools** from misconfiguration.
- Ensure only authorized personnel can modify **resource limits or compute allocations**.

### How to Use Critical Resources

To mark a resource as critical and use this feature, embed the following in your module YAML:

```yaml
critical: true
```

Tag sensitive fields with **x-ui-critical** to restrict edits.

### Permissions and Auditability

- **Permission Required**: *write\_critical\_resources* permission needed for restricted changes.
- **Audit Logs**: Logs include every critical action with details such as timestamp, user ID, and resource ID.

### Summary

The Critical Resource feature in Facets ensures that essential infrastructure components are protected from accidental or unauthorized modifications. This built-in control enhances operational safety, reinforces access controls, and provides peace of mind across engineering teams. For more information, refer to the documentation at [Facets-cloud Readme-Documentation](https://github.com/Facets-cloud/Readme-Documentation).
