# Release Notes – v1.0.0

**Release Date:** 2023-10-15  
**Author:** Jane Doe

## Overview  
This release introduces the Critical Resource feature, designed to enhance the protection of sensitive infrastructure components by implementing role-based access control and audit logging. This update is essential for maintaining operational integrity and preventing unauthorized changes to pivotal system resources.

## What’s New  

### Critical Resource  
The Critical Resource feature empowers administrators to safeguard sensitive infrastructure components.  
- **Role-Based Access Control**: Only users with the *write\_critical\_resources* permission can delete, disable, or edit critical fields.
- **Audit Logging**: Every action on a critical resource is logged, providing transparency and traceability.
- **Configuration**: Resources are marked as critical in the module YAML with `critical: true`, and sensitive fields are tagged with **x-ui-critical**.

## Product Capabilities / Configuration Changes  
- **Configuration**: To mark a resource as critical, include `critical: true` in the module YAML. Tag critical fields with **x-ui-critical**.
- **Permissions**: Users need the *write\_critical\_resources* permission to modify critical resources.
- **Audit Logs**: Audit logs record all critical actions, including timestamps, user IDs, and resource IDs.

## Enhancements  
- **User Interface Improvements**: Streamlined UI for managing critical resources, with clear indicators for critical status and permission requirements.
- **Documentation Updates**: Comprehensive guides and examples added to the [Facets-cloud Readme-Documentation](https://github.com/Facets-cloud/Readme-Documentation).

## Bug Fixes

- **Fixed**: Addressed a bug that prevented audit logs from capturing all actions on critical resources.
